# بررسی وسط‌چین بودن و اندازه‌ها — صفحات Auth (EN + FA)

**تاریخ:** 2026-09-08
**Scope (تشخیص + مستندسازی راه‌حل؛ هیچ کدی تغییر نکرد):** `web/signin.html`, `web/index.html`, `web/signup-fa.html`, `web/css/styles.css`, `web/css/fa.css`
**روش / شواهد:** رندر headless (Firefox، پروفایل `/tmp/opencode/fx2p`) از `web/signin.html` در سه viewport (1920×1080، 1366×768، 1024×768) + اندازه‌گیری پیکسلی bbox محتوا/کارت سفید + مقایسه با فایل‌های مرجع `docs/figma/*.png`.

## Verdict

چیدمان داخلیِ طراحی درست است و با آرتوربورد 1152×700 منطبق است (همین اصل پیش از این با diff پیکسلی پاس شده‌بود). مشکل از **ارائه‌ی آرتوربوردِ ثابت در برابر viewport متغیر** است:

1. **وسطِ عمودی در هیچ viewport ای رعایت نمی‌شود** — علت اصلی «وسط صفحه نیست».
2. **افقی فقط وقتی درست است که عرض پنجره ≥ 1152px باشد**؛ زیر آن محتوا می‌خسبد سمت راست و برش می‌خورد.
3. **اندازه‌ها** در مرورگر با زومِ ≠ 100٪ یا در کامپاریسون با PNGهای ۲× «به‌هم‌ریخته» دیده می‌شوند.

## علت‌های ریشه‌ای

### C1 — بدون وسط‌چین عمودی (اصلی)
`body` نه `height/min-height` دارد و نه flex/align؛ `.stage` را ارتفاع ثابت 700px می‌دهد (`styles.css:34-53`). پس ارتفاع body = 700px و محتوا به سقف پنجره می‌چسبد — پایین تصویر هر پنجره‌ی بلندتر از 700px خالی است. در صفحه‌ی لپ‌تاپ رایج (عرض viewport ~937px، 1080p) حدود 380px خالی زیر کارت می‌ماند.

### C2 — افقی: قفل عرض + برش در پنجره‌های باریک
`body { min-width: 1152px }` (`styles.css:37`) و `.stage { width:1152px; margin:0 auto }`. در viewport ≥ 1152px استیج افقی وسط است ✅؛ در < 1152px بدنه 1152px می‌شود → محتوا به چپ می‌خسبد، اسکرول افقی ظاهر می‌شود ولی با `overflow` سمت راست (کارت تا x≈1205 داخل استیج) بریده می‌شود و امکان «اسکرول به چپ» هم نیست → ظاهر «اعوجاج/بیرون از مرکز».

### C3 — همه‌جا `position: absolute` با پیکسل ثابت
card/form/SSO/OR/CTA/footer همگی مختصات ثابت‌اند (مثلاً form `left:170; top:324; width:427`). هیچ reflow/نسبتی به viewport وجود ندارد؛ هر تغییر عرض/زوم/رزولوشن، رابطه‌ی اجزا با صفحه را به‌هم می‌ریزد (محدودیتِ ساختاری، پیش‌تر هم به‌عنوان «constraint» مستند شده).

### C4 — «اندازه‌ها به‌هم‌ریخته»: سه منبع جدا
1. **تله‌ی ۲× در خروجی‌های Sign-In:** `docs/figma/Sign In (EN) Active.png` و `(FA)` به‌جای 1152×700 بـه‌صورت **2304×1400 (نسبت ۲×)** اکسپورت شده‌اند (اما `Sign Up 1/2.png` درست ۱× هستند). مقایسه‌ی بصری صفحه (رندر ۱×) با این PNG در زوم 100%، هر عنصر را **دقیقاً نصف‌اندازه** نشان می‌دهد — پرتکرارترین علت «هم‌ریختگی اندازه» برای صفحه‌ی Sign-In.
2. **زوم مرورگر / Display scaling ≠ 100%:** چون همه‌چیز پیکسل ثابت است، زوم 110/125/150% کل چیدمان را مقیاس می‌کند و در برابر PNGِ شارپِ ۲×، متن/آیکون به‌هم‌ریخته دیده می‌شود.
3. **جایگزین فونت:** متریک Urbanist (به‌جای PP Telegraf) ~۱–۳px انحراف دارد (قبلاً پذیرفته و مستند شده؛ جزئی).

## راه‌حل‌ها

### گزینه A — وسط‌چین خالص با CSS (حداقل بدون JS) ✅ پیشنهادی اگر فقط «وسطِ صفحه» مهم است
فقط به `body` اضافه/جایگزین کن (`styles.css:34-38`):
```css
body {
  font-family: var(--font);
  background: var(--canvas-bg);
  min-width: 1152px;          /* فعلاً نگه دار؛ برای C2 به B نیاز است */
  min-height: 100vh;
  display: flex;
  align-items: center;        /* وسطِ عمودی */
  justify-content: center;    /* وسطِ افقی */
}
```
- طراحی ۱:۱ حفظ می‌شود → همه‌ی diff های پیکسلی قبلی (vs ۱۱۵۲/مراجع ۱×) همچنان معتبرند.
- محدودیت: در پنجره‌های < 1152px برشِ راست و قفلِ C2 دست‌نخورده می‌ماند.

### گزینه B — مقیاس fit-to-window (پیشنهادیِ کمترین ریسک برای همه‌ی صفحه‌ها) ✅
مقیاس فقط «کوچک‌کن تا جا شود، هرگز بزرگ‌نکن» (contain، سقف 1)؛ در دسکتاپ ≥1152×700 دقیقاً ۱:۱ و وسط‌چین.
CSS (جایگزین rule ی body):
```css
body {
  font-family: var(--font);
  background: var(--canvas-bg);
  min-height: 100vh;
  display: flex; align-items: center; justify-content: center;
  margin: 0;
}
.stage { transform: scale(var(--fit, 1)); transform-origin: center; }
```
JS (یک فایل مثل `web/js/fit.js`، بدون وابستگی، روی هر ۴ صفحه خوانات):
```js
function fitArtboard() {
  var s = Math.min(1, window.innerWidth / 1152, window.innerHeight / 700);
  document.documentElement.style.setProperty('--fit', s);
}
window.addEventListener('resize', fitArtboard);
fitArtboard();
```
- با `transform-origin:center` و flex وسط‌چین روی wrapper، بصری همیشه در مرکز است، حتی وقتی کوچک می‌شود.
- در scale=1 نتیجه‌ی رندر با diff های پیکسلی جاری منطبق است (هیچ تغییری در پیکسل‌های طراحی).
- `min-width:1152px` حذف شود تا در پنجره‌های باریک اسکرول/برش افقی ایجاد نکند.
- نسخه‌ی اختیاری «fill»: حذف سقف 1 (`Math.min(...)`) → طراحی تا پر شدن پنجره بزرگ می‌شود؛ ولی از تطابق ۱:۱ با اسپک خارج می‌شود و diff پیکسلی ۱× را می‌شکند. فقط اگر واقعاً می‌خواهیم صفحه «پر» شود.

### گزینه C — بازآرایی واکنش‌گرای واقعی (مستقیم به اسکپ فعلی نیست)
جایگزین کردن choreography مطلق با flow/grid + `clamp()` برای تایپوگرافی و `container queries`؛ نیازمند re-measure در هر breakpoint و از بین رفتن قابلیت diff مستقیم با آرتوربورد. ریسک/هزینه‌ی زیاد؛ اگر محصول آی‌پی در تبلت/موبایل نیاز شد، به‌عنوان تسک جدا (غیر از MVP ثابت) پیگیری شود.

### گزینه D — اصلاح متدولوژی مقایسه
- خروجی‌های آینده‌ی بررسی SSH از Figma را **۱× (1152×700)** اکسپورت كن، یا در مقایسه همان مقیاس را در نظر داشته باش (مثلاً PNG را در Fit/50% ببین) — از تله‌ی ۲× جلوگیری می‌شود.
- قبل از قضاوت روی اندازه‌ها: `Ctrl+0` (زوم 100%) و پنجره‌ی ≥1280px.
